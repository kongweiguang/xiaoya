# 小芽图片视频方案（历史记录）

本页记录 2026-10-05 至 2026-10-06 的旧图片视频实现与当时验收。当前人物已替换为浏览器 Live2D，旧视频发布模块、Pillow 运行依赖和 PNG 打包已移除；下文的运行方法、视频断言、PID 及指纹不作为当前使用说明。现行使用、同步、模型与分层验收见 [Live2D 说明](../docs/live2d/README.md)。`verify-avatar-room.py` 已更新为音频房间验收，要求零视频轨道。

## 使用与实现

打开 http://localhost:3000，选择“开始聊天”并允许麦克风，或直接选择“用文字聊聊”。麦克风按钮显示实际状态；设备选择位于旁边的菜单。Enter 发送文字，Shift+Enter 换行；中文输入法确认不会误发送。连接中可取消，连接及等待 Agent 总计最多 30 秒。发送失败保留草稿，挂断释放麦克风并回到待机。

角色是 8 张 1024×1024 透明 PNG，由同一母版派生。Pillow 在线程中预解码、预合成 512×512 奶油色舞台，每个表情仅缓存一帧，角色固定在原位。所有画面共享母版身体、光照和背景，只融合五官局部，说话帧仅改变嘴部，避免派生整图明暗不同造成闪烁；渲染循环以 15 fps 发布 `avatar_video` 摄像头轨道。音频继续使用标准 RoomIO，不增加音频队列。前端视频静音，唯一的 RoomAudioRenderer 播放音频。

- `domain/avatar.py` 描述表现事实和优先级；播放已开始且 Agent speaking 时才张嘴。
- `application/present_avatar.py` 将领域表现提交给表现端口。
- `infrastructure/animated_avatar.py` 负责资源加载、视频发布和回收；每个 Job 独立拥有状态和任务。
- `infrastructure/livekit_conversation.py` 转换 SDK 状态和公开播放事件，暂停保留播放事实，排空尾音或确认打断才结束当前播放。
- `bootstrap.py` 仅在房间 Job 装配数字人。启动完成并输出首帧后才发送开场白；启动失败向上传播并释放已创建资源。
- 前端每次重试创建独立 Room。权限请求无法强制取消，因此迟到的麦克风先停止、再拒绝发布，旧连接不会操作新会话。

视频运行时失败只取消视频发布，页面显示“动画暂不可用，语音仍可继续”。严重的会话错误结束聊天并提供重新连接。减少动态偏好改变时立即使用静态形象；音频和文字继续可用。

## 素材与构建

正式素材位于 `src/xiaoya/infrastructure/avatar_assets`，通过 importlib.resources 加载；网页 `public/avatar/idle.png` 和 `confused.png` 与包内对应文件字节一致。提示词见该目录 README。素材更新后运行：

```powershell
uv run python deployment/prepare-avatar-assets.py
uv build
```

Wheel 已验证含 8 张素材。素材解码、固定帧尺寸、封面一致性、状态优先级、暂停恢复、尾音结束、确认打断、初始化失败、运行时降级、并发关闭和两个 Job 隔离都有离线测试。

前端继续使用 pnpm，Next.js 生产构建仅用于检查；本机令牌接口仍要求开发模式：

```powershell
Set-Location web
pnpm exec tsc --noEmit
pnpm lint
pnpm format:check
$env:NEXT_DIST_DIR='.next-build'
pnpm build
Remove-Item Env:NEXT_DIST_DIR
```

`.next-build` 不影响运行中的 `.next` 开发缓存。模板保留的两条未使用变量及 useMemo 依赖 lint 警告不影响当前小芽页面。

## 更新本机 Agent

先核对本项目 Agent 的 Linux PID 和命令行，正常结束现有 Agent，再同步并启动。不要同时启动前台 Agent 和 systemd Agent。

```powershell
wsl -d Ubuntu-22.04 -- bash -lc 'bash /mnt/c/dev/rust/xiaoya/deployment/wsl/sync-agent.sh'
pwsh -File deployment/start-wsl.ps1
```

同步脚本只更新 `/opt/xiaoya/agent` 内的源码、素材和 uv 依赖，不管理语音模型、Ollama 或其他项目服务。Windows `.venv` 与 WSL `.venv` 分开保留。已部署的母版 SHA-256 为 `eece156d242d36ca533d9204aa760ba8e6dc682fa11bd0e6ec66fdb8c4a2497d`。

## 实际验收（2026-10-05）

真实私有房间使用 Piper 合成中文音频作为上行，LiveKit、STT、LLM 和 TTS 均为本机实际服务。两轮问题“一加一”和“二加二”分别获得 2 和 4；在较长回复播放中注入语音，成功暂停原回复并获得新的问候回复。

- 收到 329,920 个 16 kHz 音频采样，其中非零 148,060 个。
- 收到 290 帧 512×512 视频。实际画面匹配到待机、眨眼、倾听、思考、小张嘴和大张嘴；播完后回到闭嘴，打断时切换倾听。
- 一个 Agent 只发布一条音轨和一条视频轨，退出验收时断开并删除测试房间。
- 原始结果及各阶段接收画面位于 `.tools/logs/avatar-retry`。显式复验命令如下，普通 pytest 不访问真实服务。

```powershell
wsl -d Ubuntu-22.04 -- bash -lc 'cd /opt/xiaoya/agent; .venv/bin/python /mnt/c/dev/rust/xiaoya/deployment/verify-avatar-room.py --output /mnt/c/dev/rust/xiaoya/.tools/logs/avatar-retry'
```

Codex 内置浏览器检查 1440×900 和 390×844，验证语音、文字、静音、挂断、取消后重连、权限拒绝、30 秒超时、发送失败保留与重试、中文输入法、换行、视频静态降级、减少动态和主题。浏览器虚拟麦克风使用 Web Audio 注入相同的合成测试 WAV；两轮真实对话和一次打断已完成，下行音频分析发现 377 个非零采样窗口，视频连续解码且为静音视频。挂断后合成麦克风轨道为 ended，音视频 DOM 元素均为 0。

异常场景通过浏览器测试夹具模拟权限拒绝、迟到授权、数据发送失败、自动播放受阻和视频错误；房间的模型及音视频传输不做模拟。测试夹具仅注入测试页面，重新加载后清除，不进入产品代码。截图保存在 `.tools/logs/avatar-ui`，精选交付图见 `deployment/evidence/avatar`。

第一次房间验收中，STT 将“首都”识别为“手都”，导致语义断言失败。改用清晰的算术问题后完整验收通过。这仍提示本地中文识别可能误听；字幕可帮助发现误识别，用户可用文字补充。

第一版是表情循环，未实现音素级嘴型同步。以上结果代表合成音频和测试夹具验收，尚未验证用户真实麦克风、扬声器、音量或回声。当前只提供 localhost 私有部署，外网发布与生产用户鉴权不在本次范围内。

离线交付检查：`uv sync --locked`、Ruff 检查及格式检查、91 项 pytest、CLI 帮助、Wheel 构建和素材打包检查全部通过。前端 TypeScript、lint、Prettier 和 `.next-build` 生产构建通过；lint 只有模板已有的两条警告。声音被阻止后点击开启可恢复；信令断开后正常恢复仍只有一个视频轨道和一个音频元素；持续恢复失败在 30 秒后回到重新连接入口。

## 说话闪烁修复（2026-10-06）

用户反馈的闪烁来自整张派生素材轮播：即使位置固定，身体、边缘和明暗仍有细微差异。渲染器改用不变的母版底图，说话只融合嘴部，其他表情只融合眼睛及必要的嘴部，局部边缘柔化。输出帧在嘴部以外逐像素一致；所有表情在五官以外逐像素一致。原始素材、嘴型节奏、播放状态规则、视频轨道和网页布局保持原有方式。

真实私有房间完成两轮合成语音及一次播放中打断，收到 314 帧视频、340,160 个音频采样，其中非零 145,259 个。身体位移全部为 0；身体区域在 0–255 通道范围内的平均亮度总变化为 0.6012，订阅后两秒质量收敛之后的最大帧间绝对差为 0.0413，未出现持续的周期性身体闪烁。前两秒的最大变化为 2.1243，单独记录为有损编解码的初始质量收敛，不与持续播放混在一起。仍只有一条音轨和一条视频轨。结果与实际收到的说话/思考帧见 `evidence/avatar/no-flash-*`。

浏览器连续测量 120 帧，身体平均亮度变化为 0.0143，最大帧间绝对差为 0.0089；封面重现、视频元素重建、媒体流切换及舞台移动均为 0。这段浏览器测量发生在回复结束后的待机画面；说话期间的帧级结果来自上述真实房间，不能将浏览器待机测量声称为说话测量。

复验期间，另一项进行中的语音升级更新了旧 Piper 服务正在使用的虚拟环境，删除了其发音资源，导致 TTS 500。只从 uv 原始缓存补回缺失的 `espeak-ng-data`，未修改升级中的代码、模型或锁文件，直接请求确认恢复非零 WAV，浏览器也重新收到开场和长故事回复。随后升级任务停止语音服务，最后一次浏览器说话复验被服务重启中断；该次结果不算通过，也未重复启动或覆盖升级任务的服务。
