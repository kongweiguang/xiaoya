# 语音延迟优化与验收

2026-10-11，在同一台 RTX 5080／WSL 私有环境对照 `e7d87ac` 与本次修改。语音仍使用 Paraformer、DeepSeek Flash、CosyVoice 和私有 LiveKit。以下是合成素材的实测，不代表真人麦克风、扬声器或主观听感验收。

## 改动与质量边界

轮次保留 SDK 1.8.4 原有的最终转写预生成和预合成。源码及阶段日志确认：原有 `FINAL_TRANSCRIPT` 已能在轮次确认前准备 LLM 回复，SDK 在确认后才授权播放，继续说话时取消过期准备。没有把临时识别文字当成最终输入。

Silero 最少静音仍为 0.30 秒，轮次等待仍为 0.90～1.10 秒，本地检测模型仍为 `v1-mini`；VAD 打断确认仍为 0.50 秒。较短停顿门槛在已有网格中未通过句内停顿控制，因此本次没有减少等待。正在被打断的开场与已经排空的普通轮次分别观察，不能把二者混成一个总体延迟。

普通轮次另用相同的优化版 TTS 对照原策略与“新增预转写事件、确认后才合成”候选。严格排空开场后，原策略三次中两次完整通过，首声为 1822／1994ms；候选三次通过为 2137／1897／2076ms。原策略日志已在确认前 107～210ms 得到首个语义段，轮次指标均约 0.90 秒。小样本不足以推断整体分布，也没有额外收益证据，因此已撤回该轮次候选；正式版本保留原识别、轮次和预合成策略，TTS 变更见下文。

TTS 在启动预热中捕获流式首块和短句的两种声学形状。权重、精度、十步声学求解、25 token 初始块、音色、语速及采样策略保持原样。只有形状、布局、类型、设备、标量和 AMP 上下文全部匹配才重放 CUDA 图；其他形状调用同一个原模型，接单后不新增图。每次重放更新输入并复制输出，上一句音频不会被下一句覆盖。

捕获关闭 AMP 的临时权重缓存，使图自己拥有转换后的权重地址。图和掩码在初始化失败、正常退出时还原。采用官方 [PyTorch 2.8 CUDA Graph API](https://docs.pytorch.org/docs/2.8/notes/cuda.html#cuda-graphs)，没有修改供应商源码或模型文件。

短句复验另发现 TTS 偶发生成约 210ms 的量化噪声，原 SDK AudioFrame 的整体 RMS 约 0.000014，浏览器同轮次无有效声音。这是合成出口已经无声，不能归咎于前端或修改门槛算作通过。现在首块放行前只拦截全程峰值不超过三个 PCM16 量化单位的结果，以完全相同文案、语气和参数最多重试一次；第二次仍失败走原 503。正常声音、前后停顿及字节保持原样，首包前静音缓存上限 1MiB；取消或已输出音频不重试。该保护不承担 ASR 或主观音质判断。

上述是 10 月 11 日的历史保护。10 月 15 日发现它仍可能放行较弱噪声或单个尖峰，现已改为连续 60ms 的 RMS 与样本占比双门，参数及重试约束见 [人物表现实现](delivery.md)。原弱音失败和旧门反例保留；新增前后各 30 条、同文案及三预设的私有 HTTP TTS 对照，完整排空且未保存音频。首字节 p95 为 738.92→543.25ms，增量 −195.67ms，达到不超过 100ms 的限制；两批随机采样及暖机状态不同，不能据此把改善全部归因于新门。该指标不含 STT、浏览器播放或 Jev，完整对话结果另见 [当前验收记录](delivery-acceptance.md)。

## 当前结果

| 观测 | 对照 | 优化后 | 样本与口径 |
| --- | --- | --- | --- |
| 私有 TTS 首个 PCM 数据块 p50／p95 | 665／748ms | 427／526ms | 最终含无声保护版；相同四条文案 × 三种语气，各 12 条，一个热身后串行请求，完整排空 |
| 开场打断后的语音回复首声，中位数 | 2660ms | 2447ms | 基线 3 次、最终 5 次完整通过；浏览器输入最后能量窗至实际非零 PCM，最终范围 2369～2610ms |
| 开麦至倾听状态，中位数 | 695ms | 659ms | 同组早期打断；最终连续静音 PCM、短回复、结束与重开资源归零、房间约 40 秒自然回收 |
| 私有 STT／停顿／噪声／恢复 | 34 项质量门通过 | 34 项质量门通过 | 逐例识别正文一致；21 条计分样例均为 16 条精确匹配，CER p95 均为 0.0769 |
| 固定采样的完整 TTS PCM | 原生路径 | 优化路径逐字节一致 | 12 对，覆盖自然、开心、轻柔；声音仅留在内存，固定随机源只作用于隔离诊断进程 |
| 跨线程及独立 AMP 上下文的声学计算 | 266ms | 117ms | 命中图的中位数；30 次调用含变长原路径，最大数值差 0，图始终为 2 个 |

最终 TTS 首帧 p50 下降约 36%，p95 下降约 30%。最终五次浏览器复验均通过且没有控制台异常，首声中位数较基线约少 213ms。最初图版本的三次成功打断窗口首声中位数为 2414ms；后来短句失败已单独记录，未混入最终统计。浏览器小样本的中位数和范围只描述这次环境，不估计总体 p95；DeepSeek 和网络波动仍会影响整轮时间。SDK 的转写、轮次、LLM、TTS 指标存在重叠，不能直接相加或称为实体扬声器延迟。

普通随机采样的 TTS 回读出现错字：对照 10／12、首次修复版和最终保护版均 6／12 精确匹配，字符错误分别为 9／16／16。回读同时受语音 token 采样和 ASR 影响，不能据此声称准确率提升或主观自然度通过。另用固定采样分别经过完整原生／优化合成，12 对 PCM 的长度、样本值和 SHA-256 完全一致，以核对加速本身没有改写声音；正常声音的字节保留另有前后静音及极轻声测试。生产没有固定随机种子，也没有降低生成质量参数。

后端 **949 项**、ruff、格式、锁定依赖同步和 CLI 检查通过；前端 **149 项**、lint、类型、格式及生产构建通过。默认测试不联网。Jev 的空 Key 与 Mock 契约仍覆盖在离线测试内，本轮延迟使用正式 Agent；没有把 Mock 或空 Key 模式称作真实 Jev 验收。

## 失败记录与部署

最初 3000 网页进程已退出，恢复同一基线后重新采样。一个早期打断基线窗口因控制台异常整体失败，未加入三个通过样本的统计。普通轮次最初的排空前置条件不足，后改为持续 1500ms 静音并重跑双方；旧策略另有一次漏识别指令末尾、一次短回复未捕获到符合条件的首声而超时，均保留失败且不纳入成功延迟统计。这些记录不用于声称普通轮次已全面通过或延迟改善。

首轮 CUDA 图候选虽然启动就绪，但第二个完整 HTTP 请求触发 SIGSEGV；已恢复稳定 TTS 路径，补上 AMP 缓存生命周期修复、跨上下文／线程／内存复用与完整 PCM 配对，之后才重新启用。原失败没有改写成通过。

撤回轮次候选后的三次复验有两次短回复无声，随后只读出口诊断再次复现一次，原结果全部保留。新增量化噪声保护之后另开复验窗口，不把旧窗口的成功样本或首帧数值冒充最终版本结果。

原始记录与逐文件 SHA-256 在本机忽略目录 `.tools/latency-optimization-20261011/`；浏览器回执另在 `.tools/deployment-current-20261011/`。不发布音频、私有配置或运行日志。切换前逐次查询公开 RoomService，未知状态或活动会话会阻止重启；只管理本项目单元，保留配置摘要并等待公开 `worker_registered`。

声学图的显式开关为 speech 单元的 `SPEECH_TTS_FLOW_ACCELERATION=cuda-graph`，直接运行 speech 未设置时默认 `none`。启动必须完成两种预热和健康检查；捕获失败会使启动失败，不在用户首次请求中编译。需要关闭图时，在空闲后将该值改为 `none`，重载单元，重启 speech／Agent 并重新确认公开注册。

本轮更新前的源码与单元备份为 `/opt/xiaoya/releases/latency-20261011-e7d87ac-before/`。整体回滚须同时恢复备份内 Agent、speech 源码和配套 speech 单元，保持私有配置，再重载并等待模型健康／公开注册；不要只回滚其中一个文件或重置工作区。部署入口及完整操作见 [部署说明](../deployment/README.md)。
