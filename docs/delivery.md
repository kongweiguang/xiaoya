# 小芽灵动交互

## 使用与边界

不增加操作面板。小芽自动选择自然、开心、温柔、关切或好奇的神态；点头、歪头、挥手只在合适的句段启动一次。字幕合并同一次回复的分段，人物仍位于原有单页中心。声音和口型继续使用同一个 LiveKit 音频出口。

`VOICE_AGENT_EXPRESSIVE_ENABLED=true` 开启，`false` 恢复普通 TTS、原字幕与基础人物行为。开关位于 Agent 配置；浏览器连接普通 Agent 时自动保持基础表现。STT、LLM、TTS 的地址、模型和独立密钥仍由原有配置决定，没有公共地址兜底。本轮按用户确认保留现有自定义 DeepSeek；它接收文本和工具上下文，不是全私有 LLM 的验收。

本轮不增加长期记忆、第二个模型、语音框架、后台服务或工具权限。网页尊重减少动态效果，改用静态形象。

正式发行缺省关闭，待全部必过门完成后再默认启用。本机验收／预览启动器显式开启，便于试用；这不等于正式增强模型已晋级。

## 实现契约

- 领域：`DeliveryIntent` 限定五种 style 与四种 gesture，非法组合归中性；`SpeechSegment` 必须有可说正文。应用用例负责生成固定开场白的开心／挥手意图。
- LLM：逐句受控标记 `[gentle|nod]正文`，继续现有 Chat Completions 流；工具调用与用量块原样保留。句段使用公开 `FlushSentinel`，不会等完整回答才开始语音。未知、缺失、损坏标记降级；缺右括号的中文正文恢复中性。控制头在 TTS 和转写节点清理，因此字幕和已说历史不保留内部标记。
- 声音：style 映射 `neutral/happy/gentle` 三个不可变私有 TTS 客户端；`concerned` 使用轻柔，`curious` 使用自然。HTTP `instructions` 只允许自然平静、开心自然、轻柔温和三种固定模板，未知值返回400。CosyVoice3开心／轻柔使用 `inference_instruct2`，独立缓存保存同一参考音色条件，不改共享 default。
- 重试：**本地语音服务唯一拥有一次自然回退预算**。只在首块 PCM 前允许回退；已发声、取消、自然回退本身失败均不再重放。Agent 和 SDK 自动重试关闭，避免跨层重复回退。
- 取消：HTTP断开立即发出线程取消信号，等锁请求每50ms检查、拿锁后再检查；当前推理只能安全排空，不承诺 GPU 瞬间抢占。清理先等待在途迭代结束再关闭生成器，重复取消不并发关闭。用户端立即停声与后台释放锁分别验收。

## 同步与恢复

公开 `TranscriptSynchronizer` 包装现有音频与专用 `TextOutput`。SDK 的入场回调和房间连接并发，故在 `session.start` 成功返回后再次幂等装配，早于业务开场白；不修改 SDK 私有字段。用户字幕仍由 SDK 保留。

三处协议共用以下小型状态，均不含正文、音频或密钥：

```json
{"v":1,"instance":"...","revision":1,"reply_id":"...","segment_id":"...","state":"active","style":"gentle","gesture":"nod"}
```

`lk.transcription` 的流头属性包含 `xiaoya.delivery` 与 `lk.segment_id`；可靠数据主题为 `xiaoya.delivery`；只读 RPC 为 `xiaoya.getDeliverySnapshot`。`closed`保留结束段身份，空闲首次快照允许空ID。真正 Agent 的发送身份与 RPC 调用上下文由 SDK 验证。

前端先订阅，再有界重试取快照，按实例／单调序号合并。只有完全匹配当前 active 的同步字幕和实际可听 PCM 才触发表现。初次轨道／分析器准备只清口型，不能误当打断。旧字幕、旧完成回调、重复消息不复活动作；被取消回复的后续句段仍被锁住。更高序号的新回复足以恢复，不依赖每个关闭通知一定成功送达。

打断、断线、后台、换轨、静音、播放受阻会关闭口型和待执行表现；恢复不补演旧动作。RPC、控制数据或单个表情资源故障只降级表现，音频与字幕继续。WebGL丢失提供静态后备、恢复与重试入口。

## 人物交付

统一控制器每帧从确定基准合成姿态、资源表情、一次性手势、音频轻摆及物理，最后写真实口型；不累加上一帧、不引入第二套动作引擎、不按音量猜情绪。表情不能写嘴部或肢体参数。

现行正式包仍为已通过历史官方 Editor 流程的16参数模型。本轮已加载实际表情资源并增加温柔／好奇兼容表现。增强笑眼、眉角与30°手臂幅度的19参数候选已通过几何和浏览器检查，**尚未通过本轮官方 Editor 另存、重开与 SDK5.0 导出，不能作为正式模型升级交付**。候选与旧正式包分离，操作及完整晋级门见[模型接力说明](../assets/avatar/xiaoya/PRESENTATION.md)。

这是句段级自然同步，不是逐字重音或音素级全身编排。

## 部署与回滚

顺序为兼容语音服务 → Agent → 网页／匹配模型包。语音服务修改只需要同步 `services/speech/src/local_speech`；本轮依赖未变化，不升级 SDK。WSL 只管理 `/opt/xiaoya` 和 `xiaoya-` 服务；更新前核对活跃房间，正常排空已核实的 Agent 进程。

本次运行原版本备份位于 `/opt/xiaoya/acceptance-backups/delivery-20261007`，包含 speech四份原文件与 Agent原源码。优先用总开关关闭表现；需要代码回退时，在空房间边界恢复这些明确文件并正常重启本项目进程。不得删除模型、密钥、虚拟环境或停止其它服务。当前运行进程与本次日志以[本轮验收记录](delivery-acceptance.md)为准，不沿用历史PID。

## 验收口径

离线门禁包括全部Python检查及前端lint、格式、类型、测试、构建。真实接口测量按同一批固定中文样本对比；真实房间需验证上行识别、LLM、音频下行、控制状态和净字幕，另检查打断与已说历史。浏览器分别检查实际可听表现、窄屏、减少动态、WebGL恢复和缺资源降级。

合成PCM、Python RTC或浏览器虚拟麦克风均不等于用户真实设备。音频指纹、RMS、时长和粗略基频只证明有差异，不证明真人听感、音色辨识与自然度已经通过。当前结果与仍未完成的门禁单列在[验收记录](delivery-acceptance.md)。
