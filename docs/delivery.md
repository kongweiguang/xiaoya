# 唯一灵动交互链路

小芽始终使用 `ExpressiveAgent`，console 与房间只保留真实通道差异。三种声音预设为 neutral、happy、gentle；七种风格与五种手势保持原语义，不添加第二套产品模式。

## 正文与控制信息

模型内部仅使用 `[xiaoya:<style>|<gesture>]`。style 为 neutral、happy、gentle、concerned、curious、shy、surprised；gesture 为 none、nod、tilt、wave、shy、shake。none 表示不触发手势。

普通 `[happy birthday]`、`[neutrality]`、`[a|b]` 以及旧 `[happy|wave]` 全部作为正文。合法控制头只控制语音风格与角色，不进入字幕、音频或历史。损坏的保留命名空间控制区降为中性，在 `]` 或换行处恢复；缓冲上限由合法枚举推导，不猜测正文恢复位置。所有切分位置采用同一增量解析结果。

自然结束提交完整正文；取消、打断与错误直接丢弃未提交缓冲，不补说、不补演，也不为了修复控制头额外调用模型。

## 所有权与同步

会话逐项创建和登记 SDK 客户端、快照端点、工具及关闭流程。全部启动成功才交给 Job 生命周期并发送开场白；启动失败关闭已创建资源，原异常继续向上传播。

房间仍使用唯一 `v:1` 协议。角色、就绪检查和重连快照共用一个控制通道；验证 Agent SID、本地参与者 SID、修订号和播放许可。结束请求有 ACK 与超时回收。旧 `lk.expression` 无消费者路径已删除，不保留双版本适配。

浏览器 Room、AudioContext、取消信号和关闭流程归当前 Attempt 所有。待开始、连接中、通话中、恢复中、结束中状态集中管理。连接重建不清空草稿和历史，不自动提交草稿；过期连接事件不会影响新会话。

`RoomAudioRenderer` 是唯一可听音频出口；分析器只读取 SDK 音轨，不重复播放或停止 SDK 持有的远端音轨。当前 SDK 需要的 `singlePeerConnection: false` 集中保留。角色渲染器独立持有 GPU／模型，房间切换只重新绑定分析；懒加载、减少动态效果、静态后备和口型降级继续有效。

## 模型与验收

模型制作只使用已安装的官方稳定版 Cubism Editor 5.3.04。目标为 19 普通参数、0 BlendShape，并保留外部参数 ID／范围、七种风格、五种手势。新包通过官方打开、保存、关闭、重开、兼容目标导出及浏览器验收后，才能整体替换当前源工程／模型／纹理／海报／配置。

先验收闭眼＋笑眼＋视线、闭嘴＋嘴形、挥手＋头身三个组合样机。网格和图集允许重新布局，不能修改工程版本头冒充稳定版，也不能默默减少动作。原画参考姿态与静音闭嘴姿态分别验收。样机不通过时保留原运行包，见 [模型资产说明](../assets/avatar/xiaoya/README.md)。

本轮实际结果按离线检查、私有接口、完整房间、模型工程和真人设备五层列出，见 [验收记录](delivery-acceptance.md)。历史报告不算本轮通过。
